# Patches

`PanVK-rynx` is rebased onto [`zenithblue-oss/panvk-kbase-android`](https://github.com/zenithblue-oss/panvk-kbase-android) (`cf70e02b`, release `panvk-kbase-v26.3.1` / build `122i`, upstream Mesa `5a07217f034b3e50d8c7c7794f97a2df1742613b`). `build.sh` and `build-bionic.sh` first run `scripts/prepare-rc5-tree.sh` from `panvk-kbase-android` and then apply this repository's patches in filename order with `patch -p1`.

| Patch | Purpose |
| :--- | :--- |
| `0001-mediatek-private-handle-afbc-and-dmabuf-fd.patch` | When vendor AIMapper loading fails in untrusted app namespaces (`[P0A-V19-FULLPLANE] mapper load failed`), decode MediaTek gralloc `private_handle_t` (`magic == 0x03141592`, `alloc_format` at `ints[30..31]`) into the exact `DRM_FORMAT_MOD_ARM_AFBC(...)` / `DRM_FORMAT_MOD_ARM_16X16_BLOCK_U_INTERLEAVED` / `DRM_FORMAT_MOD_LINEAR` modifier and scan `native_handle_t` fds via `/proc/self/fd/%d` for the `dmabuf` fd in both `u_gralloc_fallback.c` and `vk_android_import_anb_memory`. |
| `0002-kbase-jm-sync-file-export-fallback.patch` | Keep `export_sync_file` registered on JM (`arch < 10`) kbase sync types and wait for GPU completion before returning `*sync_file = -1` (already signaled). Prevents `get_semaphore_sync_type()` from returning `NULL` and segfaulting in `vk_common_ImportSemaphoreFdKHR` / `vkAcquireImageANDROID` / `wsi.present_wait` on Mali-G77 (`arch 9`). |
| `0003-kbase-disable-drm-syncobj-copy-payloads.patch` | Do not wire `device->vk.copy_sync_payloads = vk_drm_syncobj_copy_payloads` on kbase devices (non-DRM sync types). Forces `vk_common_QueueSignalReleaseImageANDROID` onto its `QueueSubmit2` wait-to-signal path instead of failing with `VK_ERROR_UNKNOWN` (`-13`) in DRM syncobj payload copy. |
| `0004-panvk-jm-v9-point-size-in-malloc-vertex-job.patch` | Set `cfg.point_size_array_format = MALI_POINT_SIZE_ARRAY_FORMAT_FP16` in Valhall v9 `MALLOC_VERTEX_JOB.PRIMITIVE` when `vs->info.vs.writes_point_size && info->prim == MESA_PRIM_POINTS`. Fixes `gl_PointSize` (1x1 dots in `compute_nbody` and `core.point_size` fail). |
| `0005-panvk-jm-v9-compute-task-axis-and-increment.patch` | Compute `task_axis` and `task_increment` for Valhall v9 JM `COMPUTE_JOB` payloads (matching CSF's `calculate_task_axis_and_increment`) instead of hardcoding `MALI_TASK_AXIS_Z` / `1`, which collapsed 1D/2D `wg_count.z == 1` dispatches (like `compute_nbody`) onto a single shader core out of 9 on Mali-G77 MC9. |
| `0006-panfrost-android-afbc-1024b-body-align.patch` | Align non-tiled AFBC `body_offset` to `1024` bytes (`0x400`) on Android (`arch >= 6`), matching MediaTek gralloc `init_afbc` (`0x400`) and MTK `DISP_OVL` hardware scanout instead of Mesa's `128`-byte alignment (which left GPU `screencap` clean while corrupting non-solid AFBC blocks on live physical display scanout). |
| `0007-vk-android-linear-swapchain-on-fallback-gralloc.patch` | When using `U_GRALLOC_TYPE_FALLBACK` (untrusted app namespace without AIMapper, unless `PANVK_ANB_AFBC=1`), add `GRALLOC_USAGE_SW_READ_RARELY \| GRALLOC_USAGE_SW_WRITE_RARELY` in `setup_gralloc0_usage()` and propagate `GRALLOC1_*_CPU_READ/WRITE` in `vk_common_GetSwapchainGrallocUsage2ANDROID()` so gralloc allocates linear swapchain buffers (`DRM_FORMAT_MOD_LINEAR`), eliminating portrait/1080p AFBC `DISP_OVL` scanout noise while keeping AFBC on all internal render targets. |
| `0008-kbase-jm-dirty-only-import-sync.patch` | Track `nc_map_count` and `nc_dirty` in `kbase_kmod_bo_mmap()`/`munmap()` so `kbase_kmod_jm_clean_imports()` only calls `DMA_BUF_IOCTL_SYNC` on currently mapped or recently unmapped non-coherent dma-buf imports, eliminating per-submit cache flushes of unmapped 8 MB linear swapchain buffers and static vertex/index buffers. |
| `0009-kbase-jm-async-sync-file-fence-export.patch` | Implement `kbase_kmod_jm_fence_after()` using `KBASE_IOCTL_STREAM_CREATE` + `BASE_JD_REQ_SOFT_FENCE_TRIGGER` (`0x202`) so `kbase_cpu_sync_export_sync_file()` on JM (`arch < 10`) exports real async kernel `sync_file` fds on `vkQueuePresentKHR` without blocking the CPU on GPU completion. |
| `0010-panvk-jm-framebuffer-local-by-region-barriers.patch` | Avoid closing and reopening batches on JM (`arch <= 9`) when `pDependencyInfo->dependencyFlags & VK_DEPENDENCY_BY_REGION_BIT` is set with no buffer barriers and layout-preserving image barriers inside an active render pass. Sets `cfg.flags_0.primitive_barrier = true` on the subsequent v9 `MALLOC_VERTEX_JOB` draw descriptor instead, allowing on-chip tile buffer reuse and eliminating DRAM tile writeback/reload cycles. |
| `0011-panvk-v9-fp16-raster-order-and-primitive-reorder.patch` | Enable native dual-rate FP16 execution (`.shaderFloat16`, `.shaderFmaFloat16`), in-tile rasterization order attachment access (`.EXT_rasterization_order_attachment_access`, `.ARM_rasterization_order_attachment_access`, `.rasterizationOrderColorAttachmentAccess`, depth/stencil), and multi-draw (`.EXT_multi_draw`, `.multiDraw`) for Valhall v9 (`PAN_ARCH >= 9`). Enable hardware out-of-order primitive rasterization (`cfg.flags_0.allow_primitive_reorder = !any_dest_read`) in `v9_emit_malloc_vertex_job` to eliminate tile serialization stalls for non-dest-reading draws. |
| `0012-panvk-jm-intra-pass-barrier-elision.patch` | Expand in-tile barrier elision in `panvk_per_arch(CmdPipelineBarrier2)` on JM to cover all intra-renderpass barriers (`cmdbuf->state.gfx.render.bound_attachments != 0` or `VK_DEPENDENCY_BY_REGION_BIT`) with layout-preserving image barriers and no buffer barriers. Elides costly batch teardown/reopen cycles and tilebuffer DRAM flushes, preserving the on-chip tilebuffer and setting `pending_fb_barrier` for reduced barrier latency. |
| `0013-panvk-v9-earlyzs-lut-and-dcd-culling-optimizations.patch` | Enable Valhall v9 Early-ZS lookup table (`pan_earlyzs_get`) in `v9_emit_malloc_vertex_job` to kill occluded fragments prior to shader execution even with fragment discard/coverage side-effects; enable polygon bounding-box scissoring (`cfg.flags_0.scissor_to_bounding_box = polygon`); and allow intra-pass buffer barriers without batch teardown in `CmdPipelineBarrier2`. |
