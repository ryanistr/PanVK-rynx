# Patches

Applied in filename order to `apexspan-svg/mesa-panvk-mali-g57` tag `v1.2.0` by `build.sh`.
Patch bodies are kept byte-for-byte so they continue to apply to that tag.

| Patch | What it fixes |
|---|---|
| `0001-guard-ahb-path-for-glibc.patch` | The AHB-only allocation path calls helpers that are not compiled outside `__ANDROID__`; it returns `VK_ERROR_OUT_OF_DEVICE_MEMORY` early in a glibc build. |
| `0002-dma-heap-rdonly.patch` | On MT6893 every `/dev/dma_heap/*` node is `0444`, so the fork's `O_RDWR` open fails for the app uid. Falls back to `O_RDONLY`; `DMA_HEAP_IOCTL_ALLOC` and `mmap` work on that fd. Without it, exportable allocations fail and gamescope aborts with `VK_ERROR_INVALID_EXTERNAL_HANDLE`. |
| `0003-enable-valhall-gen3-arch-11.patch` | Ports arch 11 (Mali-G615/G715) wiring into the fork: genxml schema, per-arch build lists, arch dispatch, pandecode entries and model rows. The CSF side of the binary otherwise enumerates no device on a G615. |
| `0004-csf-fix-provoking-vertex-fn-address-truncation.patch` | `get_fb_descs()` held a 64-bit `fns_bo->addr.dev` in a `uint32_t`. On Android's SAME_VA kbase the address is above 4 GB, so the CSF frontend prefetched from a truncated address and every group faulted (`exception 0xc1`), cascading into DEVICE LOST. |
| `0005-kbase-report-node-rdev-as-drm-device.patch` | `panvk_physical_device_init_kbase()` left the DRM rdevs at zero, so Vulkan-to-DRM matching (including gamescope's WSI) silently failed. Reports `/dev/mali0`'s `st_rdev` as the render device. Guarded with `#ifndef __ANDROID__`; the bionic half keeps platform-reported numbers. |
| `0006-csf-single-merged-csg.patch` | Uses one merged CSG for all subqueues, with fence-wait generation reclaim instead of per-subqueue teardown. |
| `0007-csf-reported-register-count.patch` | Replaces a hardcoded 96-register file with `CLAMP((stream_features & 0xff) + 1, 96, 128)`, and sets `nr_kernel_registers` on the job-emission `cs_builder_conf` like every other builder in the tree. Under-sizing a 5th-gen part or letting the stream use a kernel-clobbered register both break command stream generation. |
| `0008-advertise-physical-device-drm.patch` | Derives `EXT_physical_device_drm` from the rdevs filled by 0005. Without it, 0005's properties are unreachable through `VkPhysicalDeviceProperties2` and gamescope logs "physical device doesn't support VK_EXT_physical_device_drm". |
| `0009-add-mali-g77-model-row.patch` | Adds the row for `PAN_PROD_ID(9, 0, 0)` — the G77's `gpu_id 0x90800011` — reusing the G57's Valhall v9 tile buffer sizes and rates. Without it the driver runs on the "Mali (unknown Valhall)" fallback with no anisotropic filtering or clock rates. |
| `0010-dump-the-real-swapchain-bo-size.patch` | Widens the native-BO debug dump from 640x480x4 only to also include 1600x720x4 (4608000 bytes), the swapchain size actually used in a session, so the guest's own post-CSYNC view of the presented buffer exists. |
| `0011-jm-merged-submit-by-default.patch` | The kbase JM queue submitted and waited for every batch in turn, leaving the GPU idle between batches; the merged one-bag-per-submit path existed but was env-gated. Makes it the default; `PANVK_MERGE_SUBMIT=0` restores the old path. |
| `0012-v9-compute-scratch-floor.patch` | A v9 compute shader that spills gets 4 KiB of scratch per thread, the minimum this generation needs; under-allocating lets the job run until the kernel stops it on timeout. |
| `0014-compat-nested-map.patch` | A second `vkMapMemory` on an already-mapped allocation returns the existing pointer (as the stock driver does) instead of `VK_ERROR_MEMORY_MAP_FAILED`; vktest `compat.nested_map`. |
| `0015-occlusion-query-batch-close.patch` | `vkCmdEndQuery` closed the batch on every query, turning an N-query pass into N submits plus N cache flushes. Keep the batch open; the available-flag WRITE_VALUE barrier still orders the result. |
| `0017-mrt-zero-write-mask.patch` | Keep a valid render-target format with zero channel writes when the colour write mask is 0, instead of leaving `PIPE_FORMAT_NONE` which makes the tiler overwrite preserved data. |
| `0018-exclude-zero-write-mask-from-rt-mask.patch` | Exclude attachments with a zero colour write mask from the tiler render-target mask so they keep their previous contents. |
| `0019-push-descriptor-hw-storage.patch` | Size `panvk_push_set` and meta save/restore push storage for worst-case combined image sampler stride (`MAX_PUSH_DESCS * (PANVK_MAX_PLANES + PANVK_MAX_DESCS_PER_SAMPLER)`), fixing heap/stack corruption on 32 combined image samplers (`push.max_combined_image_samplers`). |
| `0020-jm-reuse-compute-scratch.patch` | Reuse the largest per-command-buffer TLS/WLS scratch allocation across sequential compute-only batches on JM instead of allocating a fresh 92 MiB BO per dispatch (`stress.scratch_per_batch`). |
| `0021-v9-spill-helper-lanes.patch` | Emit `.force` (`VA_MEMORY_ACCESS_FORCE`) on Valhall register-spiller TLS loads/stores (`bi_load_tl`/`bi_store_tl`) so helper lanes preserve spilled values for derivatives, and apply the 4 KiB v9 TLS floor to graphics batches in `cmd_close_batch` (`stress.spill_helper_lanes`). |
| `0022-v9-fb-local-barrier-and-spill.patch` | Enable `needs_load`/`needs_store` spill tracking on `PAN_ARCH >= 9` JM so mid-pass batch splits spill and reload the framebuffer instead of re-clearing it. |
| `0023-v9-indirect-draw-and-first-instance.patch` | Implement `firstInstance` vertex attribute offset shifting, `panlib_draw_indirect_v9` indirect/indexed-indirect draw patching, and `multiDrawIndirect` (`maxDrawIndirectCount = UINT32_MAX`) on v9 JM (`core.indirect_first_instance`, `core.multi_draw_indirect_instances`, `stress.multi_draw_indirect_large`). |
| `0024-jm-reject-gs-tess-and-guard-xfb.patch` | Return `VK_ERROR_FEATURE_NOT_PRESENT` for GS/TCS/TES shader stages on `PAN_ARCH < 10` (unless `PANVK_ADHOC_DXVK=1`) and provide JM `Cmd*TransformFeedback*2EXT` entrypoints so unadvertised XFB calls do not jump to NULL. |
| `0025-panvk-android-fallback-linear-modifier.patch` | Map `DRM_FORMAT_MOD_INVALID` from `u_gralloc_fallback` on single-plane ANB/AHB images to `DRM_FORMAT_MOD_LINEAR` and guard `mod_handler == NULL` in `panvk_image_init_layouts`, preventing a SIGSEGV on Android swapchain `vkCreateImage`. |
| `0026-android-find-dmabuf-fd-in-native-handle.patch` | Scan `native_handle_t` fds for the `dmabuf` fd instead of assuming `handle->data[0]`, fixing `VK_ERROR_INVALID_EXTERNAL_HANDLE` on MediaTek gralloc where `data[0]` is `anon_inode:gralloc_extra` and `data[1]` is `/dmabuf:Gralloc`. |
| `0027-panvk-kbase-dont-set-drm-syncobj-copy-payloads.patch` | Leave `device->vk.copy_sync_payloads` NULL on kbase devices instead of setting `vk_drm_syncobj_copy_payloads`, so `vk_common_QueueSignalReleaseImageANDROID` uses `QueueSubmit2` with `kbase_cpu_sync` instead of failing DRM syncobj ioctls with `VK_ERROR_UNKNOWN`. |
| `0028-panvk-kbase-enable-async-overlap-by-default.patch` | Enable `PANVK_ASYNC` and `PANVK_OVERLAP` by default on kbase (`PANVK_ASYNC=0` / `PANVK_OVERLAP=0` to disable) so CPU command recording/presentation overlaps GPU execution with heap-split pipelining. |
| `0029-panvk-jm-v9-compute-task-axis-and-increment.patch` | Port `calculate_task_axis_and_increment` to JM v9 compute/precomp dispatches and enable `allow_merging_workgroups` instead of hardcoding `MALI_TASK_AXIS_Z` + `task_increment = 1`, which serialized 1D/2D compute dispatches onto a single core. |
| `0030-panvk-kbase-defer-sync-file-wait-to-gpu.patch` | Stop polling imported `sync_file` fds synchronously on the CPU inside `kbase_cpu_sync_import_sync_file` (and stop closing `ks->import_fd` in `import_sync_file`), instead deferring CPU waits to `kbase_cpu_sync_wait_one` and letting `panvk_kbase_jm_submit_overlap` emit `KBASE_JD_REQ_SOFT_FENCE_WAIT` GPU atoms. |
| `0031-panvk-kbase-export-sync-file-return-signaled.patch` | Drain `ks` and return `*sync_file = -1` (already signaled) in `kbase_cpu_sync_export_sync_file` instead of submitting a `KBASE_JD_REQ_SOFT_FENCE_TRIGGER` atom chained onto the device-global `async.last_atom`, which caused 1000-4000ms fence stalls under `VK_PRESENT_MODE_MAILBOX_KHR`. |
| `0032-panvk-kbase-disable-overlap-by-default.patch` | Keep `PANVK_ASYNC=1` enabled by default on kbase while disabling `PANVK_OVERLAP` by default (`PANVK_OVERLAP=1` to opt in) to isolate/avoid multi-bag tiler-heap overlap stalls. |
| `0033-panvk-kbase-disable-async-by-default.patch` | Disable `PANVK_ASYNC` by default on kbase (`PANVK_ASYNC=1` to opt in) to isolate whether asynchronous job-bag pipelining triggers the MediaTek `MDP` (`CMDQ`) 1000ms timeout under `VK_PRESENT_MODE_MAILBOX_KHR`. |
| `0034-panvk-jm-skip-noop-pipeline-barrier-batch-split.patch` | Avoid closing and reopening JM batches in `CmdPipelineBarrier2` when the current batch has no jobs/events or when all barriers in `pDependencyInfo` have `srcAccessMask == 0` and only `TOP_OF_PIPE`/`HOST` `srcStageMask`. |
| `0035-u_gralloc-fallback-decode-mediatek-afbc-modifier.patch` | Decode MediaTek gralloc `private_handle_t` (`magic == 0x03141592`, `alloc_format` at `ints[30..31]`) into the exact `DRM_FORMAT_MOD_ARM_AFBC(...)` or `DRM_FORMAT_MOD_LINEAR` modifier in `u_gralloc_fallback`, fixing AFBC-as-linear display corruption and MDP timeouts. |

0001-0003 and 0009-0010 are specific to the G77 bring-up path. 0004-0008 are CSF fixes for
the other Mali generations compiled into the same binary; they do not change arch-9 JM
submission. 0011-0012 are arch-9 JM performance fixes, derived from the faux123 PanVK
analysis in [`FAUX123-RE.md`](FAUX123-RE.md).
